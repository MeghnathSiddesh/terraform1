# What is terraform.tfstate.backup?
# terraform.tfstate.backup is a backup of a previous Terraform state snapshot. When you use Terraform's default local backend
# Terraform keeps the current state in terraform.tfstate and normally saves the previous state as terraform.tfstate.backup when writing a new state
# Think of it like saving a previous version of a document before replacing it with an updated version.
# It acts as a disaster recovery fallback. If something goes wrong during an apply (such as a sudden power outage, a crash, or a corrupted state write), your previous working state isn't permanently lost—it is safely stored in the .backup file.
# you can recover by:
# Deleting or moving the corrupted terraform.tfstate file.
# Renaming terraform.tfstate.backup to terraform.tfstate.

# Without state, Terraform may no longer know which AWS resource IDs belong to your declared terraform resources. It could propose creating duplicate resources or otherwise produce an incorrect plan.


# never update/delete the contents of state file manually, becuase your state file may go corrupted and your resources will not get tracked
# you should only edit or update the state file through terraform commands like plan / apply etc which will not corrupt the file or it will not remove resources from track

 terraform state list \
 
 command is used to display a list of all the resources currently tracked in your Terraform state file.

What it does:
Inventory Check: It queries your state file (terraform.tfstate or your remote S3 backend) and prints out the names and resource types of everything Terraform currently manages for that workspace.

Reads Local/Remote State: It doesn't query AWS or the real world; it only looks at what is recorded in the state file.
-----------
terraform state show <resource_name>
-->terraform state show aws_resource_type.nameofresourceinterraformfile
ex:terraform state show aws_s3_bucket.bucket

used to display the detailed attributes and current values of a specific resource tracked inside your Terraform state file.
terraform state show lets you inspect everything Terraform knows about a single resource.
Shows Real Values: It displays attributes like IDs, ARNs, tags, region settings, and any auto-generated values assigned by the cloud provider.
it reads exclusively from your state file (local or remote backend like S3) and does not make live calls to AWS.

----------------------
terraform state rm <resource_name>

command is used to remove a specific resource from Terraform's state file tracking, without actually deleting the real-world infrastructure in the cloud.
Unlinks Management: It tells Terraform: "Stop keeping track of this resource in the state file."
Leaves Cloud Resource Intouched: The actual resource (like your S3 bucket or EC2 instance) remains fully running and safe in AWS.

--------------------

terraform state mv <source> <destination>

command is used to move or rename a resource's address within your Terraform state file.
Updates State Metadata Only: It tells Terraform to change the name or path of a tracked resource inside the state file.
Does Not Touch Real Infrastructure: It makes zero API calls to AWS. Your actual cloud resources remain completely untouched, running, and safe.

Imagine you have this resource in your code and state file:
resource "aws_s3_bucket" "old_name" {
  bucket = "my-bucket-xyz"
}
Later, you decide you want to rename it in your .tf file to something cleaner, like aws_s3_bucket.new_name.
If you just change the name in your code and run terraform plan, Terraform will look at the state file, see aws_s3_bucket.old_name, notice it's "missing" from the code, and assume you want to destroy the old bucket and create a brand new one (- then +). Plan: 1 to add, 0 to change, 1 to destroy.
To prevent Terraform from destroying your real-world resource, you use terraform state mv:
Change the name in your .tf file to aws_s3_bucket.new_name.
terraform state mv aws_s3_bucket.old_name aws_s3_bucket.new_name

terraform state mv aws_s3_bucket.bucket1 aws_s3_bucket.bucket12

Other common uses:
Moving resources into modules: If you decide to organize your code into a reusable module, you can use terraform state mv to shift a resource into that module's address space without recreating it.

terraform state pull

command downloads and outputs the current state from your backend (such as your S3 backend) directly to your terminal screen as raw JSON.
Reads Remote State Locally: If your state file is stored remotely (like in an S3 bucket), you can't easily open it with a local file editor. This command fetches it and displays the entire contents in your terminal.
Read-Only: It does not modify anything; it just prints the state data to standard output (stdout).
